Video service

Video server

The boombox plays video through the Jellyfin API — it authenticates with an API key, proxies transport server-side, and hands playback to Jellyfin's web and native clients. Because that boundary is a defined API, the video server is swappable. Today the supported, tested one is Jellyfin itself — it even ships on the device by default — and this catalog has room for more.

Set it up

Jellyfin

Jellyfin is a free, self-hosted media server. The boombox bundles one on the device against ~/Videos for zero-config out of the box (see Setup → Video) — but moving it onto a real server gives it the CPU to transcode comfortably, which a Pi 5 can't do for 4K/HDR. The servers/ directory ships a Docker Compose stack that stands up your own.

1. Stand it up with Docker Compose

Copy the example env, set your media path and ports, and start the stack. The same compose file also brings up Navidrome for music (see the music-server guide); you get both from one up.

jellyfin-up.sh 
cd servers
cp .env.example .env
$EDITOR .env          # set MUSIC_DIR, VIDEO_DIR, PUID/PGID, TZ, ports
docker compose up -d          # starts Jellyfin (:8096) + Navidrome (:4533)
docker compose ps             # jellyfin should show (healthy) within ~40 s

Your VIDEO_DIR is bind-mounted read-only into the container as /media, so Jellyfin scans your library but can never mutate it. Server state — users, libraries, and watch history / resume points — lives in the named jellyfin-config volume at /config (jellyfin-cache holds regenerable thumbnails and transcodes). Back up jellyfin-config; skip the cache.

2. Create the admin & a Movies library

Jellyfin runs its own first-launch wizard — there's no headless seed. On the LAN, open http://<host>:8096, create the admin user with a strong, unique password (don't reuse the boombox's 6-digit LAN credential), and add a Movies library pointed at /media (that's your VIDEO_DIR inside the container).

The default Movies library only indexes files named Title (Year).ext — e.g. Sintel (2010).mp4. Anything else is silently skipped. For arbitrary files switch the library to Mixed Content, or add a second library of the right type. For direct play on modest hardware, encode to H.264 / AAC; 4K / HDR forces a software transcode a small host can't keep up with.

3. Reach it from outside your home (optional)

On the LAN you're done — the boombox needs only a reachable URL and an API key. To watch when the boombox travels, expose the server behind TLS. The shipped Cloudflare Tunnel overlay dials out, so you open no router ports; tell Jellyfin its public origin so generated links are correct:

jellyfin-expose.sh 
# Reach both servers from outside the home WITHOUT opening router ports
docker compose -f docker-compose.yml -f docker-compose.cloudflared.yml up -d

# Map the tunnel hostname to http://jellyfin:8096 in the Cloudflare Zero Trust
# dashboard, then tell Jellyfin its public origin and re-up:
echo 'JELLYFIN_PUBLISHED_URL=https://video.example.com' >> .env
docker compose up -d
# (Router port-forward + a reverse proxy with TLS is the other supported path.)

Exposing a media server is the highest-risk step in the project. Jellyfin uses an API key and native apps send passwords, so TLS is non-negotiable — never expose it as raw HTTP. Use a strong, unique password, keep the pinned image patched, and add rate-limiting at the edge. A mesh VPN (Tailscale / WireGuard) or Cloudflare Access in front is safer than a bare public endpoint. Full walkthrough in HOME-SERVERS.md.

4. Point the boombox at it

Every Jellyfin address on the boombox — the transport proxy, the WATCH button's kiosk navigation, and both library-refresh triggers — resolves through one variable, BOOMBOX_JELLYFIN_BASE. Set it, drop in an API key created in the server's Dashboard → API Keys, and restart the consumers:

jellyfin-connect.sh 
# 1. Point the device at your server (loaded by the units already)
echo 'BOOMBOX_JELLYFIN_BASE=https://video.example.com' \
    | sudo tee -a /etc/boombox/jellyfin.env

# 2. Store the API key from Jellyfin Dashboard → API Keys (single line)
printf '%s\n' 'PASTE_YOUR_JELLYFIN_API_KEY' \
    | sudo tee /etc/boombox/jellyfin-api-key >/dev/null
sudo chmod 0640 /etc/boombox/jellyfin-api-key

# 3. Restart the consumers so they pick up the new base + key
systemctl --user restart boombox-remote boombox-buttons

The on-device Setup Wizard has a Video step that does the same thing for you — this manual path is the reference and the way to change it later. Set the one env var and the whole device, touchscreen included, follows your server.

Connect the boombox

The wizard does the pairing — this page just stands up the server.

You don't wire the boombox up here. A fresh device auto-launches a first-run Setup Wizard that walks through Wi-Fi, the music library, video, and remotes — its Video step points the device at the bundled server or your own. See the Setup & services reference for the wizard and every manual equivalent; don't duplicate it, just follow it once the server is up.

  • Setting up music too? The same servers/ stack runs Navidrome — see the music-server guide.
  • Already have the boombox running? Change the target any time by editing /etc/boombox/jellyfin.env and restarting the consumers.
  • Prefer the bundled on-device server? It's the default — nothing to configure. See Setup → Video.
